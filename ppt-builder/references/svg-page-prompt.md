# SVG Bento Grid 页面生成提示词

将下列提示词用于逐页生成 SVG。目标是得到适合 `ppt-engine` native/default 导出为 PPTX 的 1280×720 页面设计。Bento Grid 布局规则为所有风格共享,各风格文件只规定本风格偏好的布局组合与密度。

## Placeholders

- `{{DECK_TITLE}}`:整份 PPT 标题
- `{{PAGE_NUMBER}}`:当前页码
- `{{TOTAL_PAGES}}`:总页数
- `{{PAGE_TITLE}}`:当前页标题
- `{{PAGE_CORE_MESSAGE}}`:当前页核心结论(Stage 2 详化产出)
- `{{PAGE_CONTENT}}`:当前页内容要点、数据、证据、文字素材(Stage 2 详化产出)
- `{{VISUAL_STRATEGY}}`:本页建议视觉策略
- `{{STYLE_BRIEF}}`:风格要求(来自选定 `references/styles/*.md`:受众、页型、密度、布局偏好、配色)
- `{{NOTES_HINT}}`:演讲备注提示

### 强制画布要求

- 只输出一个完整 SVG,不要输出解释文字。
- SVG 必须使用 16:9 画布:`width="1280" height="720" viewBox="0 0 1280 720"`。
- 必须包含页面背景 `<rect>`。
- 页面应适合作为 PPT 页面直接展示,不能依赖外部 CSS、HTML 或脚本。

### Bento Grid 布局(所有风格共享)

这是一种灵活的网格系统,其布局应由内容本身的需求驱动,而非僵硬的模板。通过组合不同尺寸的卡片,创造出动态且视觉有趣的布局。

**核心原则:**

- **灵活性**:卡片数量不固定。可以是 1、2、3、4、5 或更多个,取决于如何更好地呈现信息。
- **层级感**:使用卡片尺寸建立视觉层级。最重要的信息放在最大的卡片上。
- **留白**:在所有卡片之间保持至少 20px 间距,页面四周保留足够安全边距。

**布局组合示例:**

- **单一焦点**:一张大卡片覆盖大部分区域(如 w=1200, h=580)。适用于单一、有力的信息或详细图表。
- **两栏布局**:
  - 50/50 对称:两张等宽卡片。
  - 非对称:一张较宽卡片(如 2/3 宽度)用于主内容,一张较窄卡片(1/3 宽度)用于辅助信息、数据或图片。
- **三栏布局**:三张等宽卡片,适合并列比较三项内容。
- **主次结合**:一张大的居中卡片,两侧各一张小的垂直卡片。
- **顶部英雄式**:顶部一张宽幅"英雄"卡片,下方是 2–4 个较小的等宽卡片网格。
- **混合网格(自由度最高)**:自由混合各种尺寸的卡片,例如一个中等方块、两个小的水平矩形和一个垂直矩形。这种方式可以极大地适应不同内容的需求。

> 哪种布局组合由 `{{STYLE_BRIEF}}` 的偏好与本页内容共同决定;不要机械套模板。

### 每页充实但不堆文字墙

- 每页必须表达一个明确核心结论(`{{PAGE_CORE_MESSAGE}}`)。
- 每页含核心结论 + 支撑要点/数据 + 证据溯源三要素。
- 正文 ≥ 约 120 字(技术风格可到 ~200 字),但必须**拆成 Bento 卡片**,不得形成大段文字墙。
- 标题不过长;每个卡片有明确功能:结论、证据、数据、步骤、风险、建议等。
- 不得虚构数据或事实,只能用 `{{PAGE_CONTENT}}` 提供的信息。

### Native-PPTX-friendly SVG 约束

为提高 `ppt-engine` native/default 导出为可编辑 PPTX 的成功率,必须遵守:

1. 使用基础 SVG 元素:`<rect>`、`<circle>`、`<ellipse>`、`<line>`、`<path>`、`<polygon>`、`<polyline>`、`<text>`、`<tspan>`、`<image>`、`<g>`。
2. 样式尽量写成元素上的显式属性,例如 `fill`、`stroke`、`font-size`、`font-weight`、`font-family`、`rx`、`opacity`。
3. 禁止使用 `<style>`、CSS class、外部 CSS、`<foreignObject>`、`<symbol>`/`<use>`、`textPath`、`@font-face`、SVG 动画、`<script>`、事件属性、`<iframe>`、`mask`。
4. 不使用 `rgba(...)`,透明度使用 `fill-opacity` / `stroke-opacity`。
5. 不在 `<g>` 上设置 `opacity`;需要透明时设置到每个子元素。
6. 图标优先用可编辑的基础形状或路径;不要使用无法解析的 symbol/use 复用。
7. 文本使用真实 Unicode 字符;XML 保留字符必须转义:`&amp;`、`&lt;`、`&gt;`、`&quot;`、`&apos;`。
8. 字体栈必须以常见系统字体结尾,例如 `Microsoft YaHei`、`SimSun`、`Arial`、`Times New Roman`。
9. 同一逻辑行的混合样式应使用一个 `<text>` 加内联 `<tspan>`,不要拆成多个相邻 `<text>`。
10. 多行文本可用 `<tspan x="..." dy="...">` 分行;不同列或不同卡片使用独立 `<text>`。
11. 顶层内容应按语义分组为 `<g id="...">`,例如 `header`、`card-1`、`card-2`、`footer`,便于 PPT 中选择和动画。
12. 目标是 native editable PPTX 时,避免复杂滤镜、任意裁剪、像素级透明合成等难以转换的效果;必要时用基础形状、渐变、低透明度矩形替代。

### 输出质量要求

- 页面必须能独立表达一个核心观点。
- 视觉装饰必须服务信息表达,不要过度装饰。
- 输出必须是格式良好的 XML/SVG。
