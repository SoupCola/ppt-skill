# 风格预设:技术风格(工程评审型)

`technical-deepdive` —— 面向架构师/同行的工程评审型技术稿。架构图 + 方案对比 + 权衡决策,信息密集。本文件只规定本风格特有的受众、页型、密度、布局偏好与视觉;**Bento Grid 布局规则以 `svg-page-prompt.md` 共享为准**,不重复定义。

## 适用场景

- 架构评审 / 方案评审 / 技术评审 / 技术分享(工程导向)
- 受众:架构师、同行工程师、技术评委

## 核心基调

- **方案+权衡**:不只讲"是什么",更讲"为什么这样选 / 替代方案 / 代价"。
- **图驱动**:架构图、时序图、对比矩阵优先于纯文字。
- **信息密集可读**:密集但靠 Bento 分块与层级保持可读,不堆文字墙。

## 受众与密度

- 受众:架构师 / 同行工程师 / 技术评委
- 信息密度:每页 1 核心结论(技术判断)+ 架构图/对比 + 权衡说明
- 正文 ≥ ~200 字,拆成卡片
- 含数据/指标/取舍依据

## 推荐页型序列

现状/问题 → 方案概述 → 架构总览 → 关键模块/流程 → 方案对比(2×2 或对比矩阵)→ 性能/实验数据 → 风险与权衡 → 演进/下一步 → Q&A/附录

## Bento 布局偏好(在共享规则内选用)

优先使用以下组合,承载密集信息:

- **单一焦点**:1 张大卡放完整架构图/时序图(w≈1200, h≈580)。
- **混合网格(自由度最高)**:中等方块(架构层)+ 两个小水平矩形(指标/约束)+ 一个垂直矩形(决策说明),承载多维度技术信息。
- **顶部英雄式**:顶部宽幅架构/方案图,下方 2–4 个等宽卡(各模块/各方案要点)。
- **三栏布局**:三方案并列对比。
- **主次结合**:居中大架构图,两侧小卡放非功能性指标/约束/风险。

避免:仅用两栏对称这种过于稀疏的布局承载密集技术内容。

## 配色与视觉倾向

- 主色:技术深色(深蓝/墨绿/石板灰),辅以 1 个强调色标关键路径/决策。
- 背景:浅灰或白;架构图区块可用深色卡片突出分层。
- 图表:架构图/时序图/对比矩阵/性能柱状/折线,鼓励使用。
- 代码/公式:用等宽字体 `<tspan>` 或独立 `<text>` 块,深色卡片底。
- 不用:商务渐变、装饰阴影、与信息无关的图标。

## 充实度自检

- [ ] 每页有一个可论证的技术判断(不是"介绍某模块",而是"为何这样设计")?
- [ ] 含核心结论 + 支撑(架构/数据/对比)+ 证据/取舍依据?
- [ ] 正文 ≥ ~200 字且拆成卡片(无文字墙)?
- [ ] 关键架构/对比以图为主,文字辅助?
- [ ] 无虚构数据/性能指标,只用了输入材料?
