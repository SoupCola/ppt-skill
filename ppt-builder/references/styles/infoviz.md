# 风格预设:信息可视化图文型(Info-Viz)

`infoviz` —— 面向**军工 / 科技 / 工业 / 政府 / 集团规划类**专业汇报的「图文并茂」风格:固定三段骨架 + 模块化卡片 + 丰富专业插图。强调内容逻辑、视觉层次与技术表达,通过合理版式、信息层级与高质量插图让观众快速理解内容逻辑。追求简洁、现代、专业,而非强烈视觉冲击。本风格的核心是**每页约 4 张专业插图**(技术图 + 场景占位),区别于纯文字汇报与纯架构技术评审。Bento 布局共享规则以 `svg-page-prompt.md` 为准,不重复定义;本文件给出被实战验证为「好出、好导出、好看」的具体参数。

## 适用场景

- 军工 / 科技 / 工业 / 政府 / 集团科技创新 / 专项规划 / 项目汇报 / 成果展示
- 受众:集团领导、规划评审、技术同行、行业评委、客户决策者(需快速理解内容逻辑)

## 固定画布与三段几何(实战参数)

- 画布 `1280×720`,`viewBox="0 0 1280 720"`,根 `<svg>` 设 `font-family="Microsoft YaHei, SimHei, Arial"` 继承到所有文字,减少逐元素重复。
- 背景白底 `<rect x="0" y="0" width="1280" height="720" fill="#FFFFFF"/>`。
- 每页**固定三段骨架**(像素坐标可直接套用):
  1. **标题区 y0–92**:左侧 6×40 深蓝竖条 `rx=3` + 24px 粗体标题;右上角 13px 灰字 `单位 · 标题 · P页/总页` `text-anchor="end"`;`y=92` 一条 `#D8DEE6` 1px 分隔线。总结页可弱化三段(无结论条)。
  2. **主体区 y100–624**:模块化卡片,按信息流排布。
  3. **总结强化区 y628–700**:`#EEF3FA` 圆角条(rx=10)+ 左侧 4×40 深蓝竖条 + 「核心结论」小标 + 16px 结论句,关键短语用 `<tspan font-weight="bold" fill="#C0392B">` 红色加粗。

## 配色 token(实战调色板,军工+科技+工业)

| 角色 | 色值 | 用途 |
|---|---|---|
| 主色 深蓝 | `#1B3A6B` | 标题、卡片头、主框架、深色强调卡底、流程主节点 |
| 辅色 钢蓝 | `#2E6FB0` | 次级模块、技术图次框、连接线辅色 |
| 辅色 浅蓝 | `#5B8DC0` | 技术图辅线、虚线、示意细节 |
| 浅蓝填充 | `#DCE6F2` | 技术图块底、卡内小框、深色卡内白系文字 |
| 强调红 | `#C0392B` | 关键词红字、目标/终态节点、危险/重点指标、箭头 |
| 强调红浅底 | `#FBE7E4` | 深色/红卡内辅助说明文字 |
| 正文深 | `#1F2A37` | 正文 |
| 正文灰 | `#5A6675` | 次要说明、占位说明 |
| 卡边框 | `#D8DEE6` | 卡 `rx=10` 边框 1px |
| 占位虚框 | `#B9C6D6` | B 类占位 `stroke-dasharray="6 4"` |
| 占位浅底 | `#F2F5F9` | B 类占位块底 |
| 总结条底 | `#EEF3FA` | 结论强化区底 |

> 配色按场景/行业可调,但本调色板已被验证为「军工/科技/工业规划」的高完成度默认值;换行业时主辅色三元组(主/辅/强调红)保持 3 色克制,色不过多。

## 字体与文字层级

- 字体栈 `Microsoft YaHei, SimHei, Arial`,根 `<svg>` 统一设,逐元素不再重复 `font-family`。
- 层级:页标题 24px 粗体 → 模块标题 15–16px 粗体 → 卡头 13–14px 粗体 → 正文 11–12px → 次要说明 10–11px。
- 重点信息加粗 / 强调红 / 突出数字;正文拆卡不堆墙。

## 模块卡片样式库(实战版式,可直接套)

所有卡片:`rx=10`、`stroke="#D8DEE6"` 1px 白底;或深蓝底 `fill="#1B3A6B"` 白字(强调卡)。卡头常用左 6px 深蓝竖条或顶部 36–40px 深蓝条。

1. **2×2 矩阵卡**:四等宽卡,每卡含 标题 + 3–4 条要点 + 红色关键词行 + 1 个 B 占位(典型密度)。
2. **三段流程卡**(横向 / 纵向):3 卡串联,卡间红色三角箭头(`polygon` 手绘箭头),每卡带 1 个 B 占位(适合 技术攻坚→突破→标准 类路径)。
3. **中心辐射图**:中心 hub 节点 + 左右/四周子节点 + 连接线 + 手绘箭头;适合总览/体系图(A 类)。
4. **分层架构堆叠**:纵向 3–4 层条带 + 层间红箭头;适合平台/数据架构(A 类)。
5. **横向链路图**:N 步节点 + 箭头串联;适合制导链路/数据流(A 类)。
6. **跨部门辐射 + 虚线推广**:hub 连多部门实线 + 一条虚线表示「推广」(A 类)。
7. **指标卡 / 护城河条**:横向 3–4 指标卡,末卡用红底强调终态。
8. **深色强调卡**(强调版式):深蓝底 + 浅蓝文字 `#DCE6F2` + 红色关键词 `#FBE7E4`;用于「目标 / 维度三 / 跨越增长」等强结论区,与白卡形成对比。
9. **转型/对比箭头条**:现状卡 → 红箭头 → 目标红卡,一行内表达「从 X 到 Y」。

## 插图密度标准(本风格核心,区别于其余两风格)

- **每页约 4 张插图**为基准密度(已验收为「满意」档):1 张 A 类技术图 + 1–3 张 B 类场景占位;或纯 2×2 四 B 占位;矩阵/总览页可用 4 B 占位。
- **计数规则(重要)**:只有 B 类场景占位与 A 类完整技术图计入插图密度;**卡内/角标的小图标(icon)不计入**——小图标仅作点缀,不能用来凑密度。
- 每页仍保留一句核心结论(总结条)+ 3–5 条要点 + 红色关键词,避免为图牺牲信息。
- 单一技术图页(纯流程/纯架构)若图偏单薄,补 1–3 个 B 占位凑到 ~4。

## A 类技术插图规范(原生 SVG,非占位)

- 由 AI 用基础形状/路径直接绘制,导出后可编辑;**不用**占位机制、不用图片。
- 模块框 = 圆角矩形;**连接线**用 `<line>` + **手绘箭头** `<polygon points="...">`(三/四点三角,填强调红或主色),不用 SVG `marker`(Native-PPTX 不友好)。
- 数据可视化:突出核心结论而非堆数据;关键指标用高亮/标注框。
- 架构图:清晰模块框 + 连接 + 方向箭头,突出模块关系与数据流;避免装饰。

## B 类场景占位规范(可替换,实战实现)

每个图位用语义化分组 `<g id="img-slot-N">`(N 从 1 递增),固定四件套:

1. 轻框 `<rect>`(圆角 8、`fill="#F2F5F9"`、`stroke="#B9C6D6"` 1.5px、`stroke-dasharray="6 4"`)圈出图片区;
2. AI 用基础形状/路径绘制的主题示意图(武器、无人机、设备、火箭等抽象示意);
3. 底部 24px 标签条 + `📷 占位图 · 可替换` 文字(`text-anchor="middle"`,底条用 `#1B3A6B` `fill-opacity="0.85"`);
4. 紧邻注释 `<!-- IMAGE_SLOT: <主题描述>; 建议尺寸: <w>x<h>; 替换提示: <真实图片建议> -->`。

深色/红底卡内 B 占位:框用 `fill="#FFFFFF" fill-opacity="0.08"` + `stroke="#9FB6D6"` 虚线,底条 `fill="#FFFFFF" fill-opacity="0.15"` 白字。后期替换:整组 `<g id="img-slot-N">` 换成 `<image href="..." xlink:href="...">`,或在 PPTX 中直接插图覆盖该区。

## 总结强化区规范

`#EEF3FA` `rx=10` 条 + 左 4×40 深蓝竖条 + 11px 粗体「核心结论」小标 + 16px 结论句。关键短语用 `<tspan font-weight="bold" fill="#C0392B">` 红加粗(注意 `<tspan>` 在同一 `<text>` 内连续使用,导出为独立可编辑文本 run)。总结页/致谢页可弱化或省略该条。

## 深色强调卡模式

深蓝底 `#1B3A6B` + 白字 + `#DCE6F2` 辅助说明 + `#FBE7E4` 红浅底文字;用于「目标 / 终态 / 跨越增长」等强结论模块,与白卡对比;卡头可叠 36–40px 红条 `#C0392B` 表示「重点维度」。

## Native-PPTX-friendly 硬约束(导出可编辑必备)

SVG 必须可被 `svg_to_pptx.py` 转为原生 DrawingML(可编辑、非整图)。**禁止**:CSS/`<style>`、`foreignObject`、`<symbol>`、`<use>`、`<marker>`、`filter`、`mask`、`rgba()`、group `opacity`、渐变 `<linearGradient>` 大面积铺底、`transform` 嵌套(必要时仅浅层 `translate` 且转换器会内联,但尽量直接给绝对坐标避免位移错位)。圆角矩形会被 `finalize_svg.py` 自动转 `<path>`。阴影用「偏移矩形 + `fill-opacity`」模拟,不用 filter。每页顶层结构用语义化分组 `<g id="header|body|conclusion|...">`,导出后每页约 4–6 个顶层 shape(背景 + 各大区分组),分组内子元素转为嵌套组,转换器会计算正确坐标。

## 标题区 / 页脚约定

- 每页标题区右上角:`单位 · 主题 · P页/总页` 灰字。
- 正文分区起首可用 12px 粗体红字 `▌小节名` 作锚点(如 `▌四板块协同`)。
- 总结/致谢页(P25)可深蓝铺底 + 白字 + 谢谢页脚,弱化三段。

## 推荐页型序列

封面(主题+抽象主视觉) → 目录(编号列表+流程装饰) → 总体目标(指标卡+架构) → 各板块总览(中心辐射/2×2) → 各方向详页(流程 A + 场景 B) → 场景占位页(2×2 四 B) → 架构/制导链路(密集 A) → 转型/路径页(箭头条+维度卡) → 总结(板块协同+展望) → 致谢。
